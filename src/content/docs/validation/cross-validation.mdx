## Intuition & Overview

One validation split can be lucky or unlucky. Cross-validation runs several rounds, each holding out a different part of the data, so every sample is used for validation exactly once. The average is steadier, and the spread shows how much the score depends on the split.

## Mathematical Foundation

With the data divided into folds $F_1, \dots, F_k$, and $\hat{f}^{(-i)}$ the model trained without fold $i$:

$$
\text{CV} = \frac{1}{k} \sum_{i=1}^{k} \text{score}\left( \hat{f}^{(-i)}, F_i \right)
$$

Larger $k$ trains on more data per round, which reduces pessimism in the estimate, but costs $k$ training runs. Values of 5 and 10 are the common compromise.

## Step-by-Step Breakdown

1. Shuffle the data, unless order matters, and divide it into $k$ folds.
2. Hold out one fold.
3. Fit all preparation and the model on the remaining folds.
4. Score on the held-out fold.
5. Repeat for each fold, then report the mean and standard deviation.
6. Refit the chosen configuration on all the training data.

from sklearn.model_selection import StratifiedKFold, cross_val_score
from sklearn.neighbors import KNeighborsClassifier
from sklearn.pipeline import make_pipeline
from sklearn.preprocessing import StandardScaler

model = make_pipeline(StandardScaler(), KNeighborsClassifier(n_neighbors=5))
folds = StratifiedKFold(n_splits=5, shuffle=True, random_state=0)
scores = cross_val_score(model, X_train, y_train, cv=folds)
print(scores.mean(), scores.std())

## Strengths, Limitations & Real-world Trade-offs

**Strengths**

- It uses all the training data for both fitting and validation.
- It reveals how sensitive a score is to the split.

**Limitations**

- It multiplies training cost by $k$, which is often too expensive for large neural networks.
- Plain k-fold is wrong for time series and grouped data. See the [overview](/validation/overview/).
- Folds overlap, so their scores are not independent. Treat the spread as a rough guide, not a formal error bar.

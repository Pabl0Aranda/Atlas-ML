Many algorithms never see your data as you do. They only ask one question: how far apart are these two samples? Whatever answers that question decides what counts as "similar", so it quietly shapes the model. [KNN](/algorithms/knn/) picks neighbors with it, [k-means](/algorithms/k-means/) assigns <Term id="cluster">clusters</Term> with it, [DBSCAN](/algorithms/dbscan/) measures density with it, and [hierarchical clustering](/algorithms/hierarchical-clustering/) merges groups with it.

There is no single correct distance. The right one depends on what your data is and what "similar" should mean for your problem.

| [KL divergence](/distance-metrics/distributions/) | Probability distributions | Training generative and probabilistic models | No |
| [Wasserstein](/distance-metrics/distributions/) | Probability distributions | Comparing distributions that barely overlap | Yes |

## What makes a true metric

In mathematics, a distance $d$ is a metric only if it meets all of these rules for any $x$, $y$ and $z$:

$$
d(x, y) = 0 \iff x = y
$$

$$
d(x, y) = d(y, x)
$$

$$
d(x, z) \le d(x, y) + d(y, z)
$$

The first says only identical things are at distance zero. The second is symmetry. The third, the triangle inequality, says a detour is never shorter than the direct route.

Plenty of useful measures break these rules, and that is fine. It only matters when an algorithm relies on them. For example, some fast neighbor-search structures use the triangle inequality to skip samples, so they cannot be used with a measure that breaks it.

## Which one should I use?

1. **Numeric features on similar scales:** start with Euclidean.
2. **Numeric features with outliers, or many dimensions:** try Manhattan, which does not square differences.
3. **Correlated features:** use Mahalanobis, or decorrelate first with [PCA](/algorithms/pca/).
4. **Text or embeddings:** use cosine, because document length should not count as a difference.
5. **Sets or tags:** use Jaccard.
6. **Categories or binary codes of equal length:** use Hamming.
7. **Strings of different lengths:** use Levenshtein.
8. **Time series with shifts in time:** use dynamic time warping.
9. **Probability distributions:** use KL divergence as a training loss, and Wasserstein to measure how far apart two distributions are.

## Scale your features first

Geometric distances add up differences across <Term id="feature">features</Term>, so a feature measured in thousands drowns out one measured in fractions. Income would decide everything and age would barely count. [Scale your features](/data-preparation/processing/) before you use any of them. Mahalanobis is the exception, because it accounts for each feature's spread by itself.

Distances also lose contrast in high dimensions, where the nearest and farthest samples end up at similar distances. This is one reason [KNN](/algorithms/knn/) struggles with many features.
